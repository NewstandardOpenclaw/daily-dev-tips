今日は「イベント駆動・監視・データ処理」を横断して、試験で混同しやすい要点を3分で復習できる構成です。

Topic 1: SQS vs SNS vs EventBridge

定義: SQSはキュー、SNSはPub/Sub通知、EventBridgeはルーティング中心のイベントバス。

重要性: DVAは「要件に対する最適サービス選定」を頻出で問う。

使い分け:
・確実なバッファリング/再処理 → SQS
・1イベントを多数サブスクライバへ即時配信 → SNS
・SaaS/AWSサービス横断の条件分岐ルール配信 → EventBridge

誤解: 「EventBridgeがあればSQS不要」ではない。疎結合と再試行/デッドレターの責務は別。

3分要点: Fan-outはSNS、耐久キューはSQS、条件ルーティングはEventBridge。DLQ設計をセットで考える。

Topic 2: Lambda 同期呼び出し vs 非同期呼び出し

定義: 同期は呼び出し元が応答待ち、非同期はイベント投入後にバックグラウンド実行。

重要性: レイテンシ要件・失敗時挙動・再試行戦略の設計判断が問われる。

使い分け:
・API応答が必要 → 同期（API Gateway→Lambda）
・処理完了を待たない業務イベント → 非同期（S3/SNS/EventBridge）

誤解: 非同期なら「絶対成功」ではない。失敗イベント送信先（DLQ/オンフェイラー）設定が必要。

3分要点: ユーザー体感速度は同期、耐障害性と疎結合は非同期。再試行回数/宛先設定を暗記。

Topic 3: CloudWatch Logs Insights の基本クエリ設計

定義: ログを対話的に検索・集計できるマネージド分析機能。

重要性: DVAで「障害調査の最短手段」「メトリクス化前の一次調査」が問われやすい。

使い分け:
・即席分析/絞り込み → Logs Insights
・長期可視化/アラート → Metric Filter + CloudWatch Alarm

誤解: Logs Insightsは保存先ではない。保存はCloudWatch Logs、分析はクエリ実行。

3分要点: fields→filter→stats の順で考えると速い。まずエラーレート可視化。
