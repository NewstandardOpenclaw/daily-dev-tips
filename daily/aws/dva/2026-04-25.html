DynamoDB 条件付き書き込み
  • 定義: 条件式（ConditionExpression）を満たす場合のみ更新/作成する制御。
  • 重要性: 同時更新時の上書き事故や二重登録を防げる。
  • 使い分け: 競合防止は条件付き書き込み、履歴監査は別テーブルやStreamsで補完。
  • 誤解: トランザクションを使わなくても常に整合性が担保されると思うこと。
  • 3分要点: 「競合が起きる更新」には条件式を先に入れる。

参考: DynamoDB Condition Expressions

Lambda + SQS 可視性タイムアウト
  • 定義: 受信済みメッセージを一定時間他コンシューマーから見えなくする設定。
  • 重要性: 処理時間より短いと重複実行→DLQ増加の連鎖を招く。
  • 使い分け: VisibilityTimeout は処理時間に合わせ、失敗分離はDLQで管理。
  • 誤解: リトライ回数だけ増やせば安定するという考え。
  • 3分要点: 「処理時間・可視性・DLQ閾値」はセットで調整する。

参考: Using Lambda with SQS

API Gateway 認証方式の選び分け
  • 定義: IAM / Cognito / Lambda Authorizer でアクセス制御する仕組み。
  • 重要性: 認証方式の選択で運用コストとセキュリティが変わる。
  • 使い分け: 社内APIはIAM、ユーザー向けはCognito、特殊要件でLambda Authorizer。
  • 誤解: 何でもLambda Authorizerで統一すれば柔軟で正解という発想。
  • 3分要点: 「利用者と要件」で認証方式を決めるのが最短。

参考: API Gateway Access Control
