日付: 2026-05-23 (JST) / テーマ: API Gateway Lambda オーソライザー（JWT/Cognito含む）の設計判断
定義

Lambda オーソライザーとは何か

Lambda オーソライザーは、API Gateway でリクエスト受信時に認可判定を行う仕組み。 HTTP API では JWT オーソライザー（Cognito/OIDCトークン検証）を使える。 REST API では Lambda オーソライザー（TOKEN/REQUEST）で柔軟な判定ロジックを実装できる。

DVAでは「どの認可方式を選ぶべきか」が頻出。

重要性

なぜ重要か（試験・実務）

認可方式の選定は、レイテンシ・運用負荷・セキュリティ境界に直結する。 DVAでは「最小実装で安全に公開するには？」という設問で、Cognito/JWT と Lambda オーソライザーの使い分けが問われる。

使い分け

JWT / Lambda オーソライザー / IAM の使い分け

  • JWTオーソライザー: Cognitoや外部IdPのJWTを検証するだけなら最優先（軽量・低運用）。
  • Lambdaオーソライザー: 独自の属性判定・外部DB参照・複雑なABACが必要な場合。
  • IAM認可: AWS内サービス間アクセスやSigV4前提のクライアントに向く。
誤解

よくある誤解

  • 「Lambdaオーソライザーの方が常に高機能で正解」→ 単純JWT検証なら過剰実装。
  • 「認証と認可は同じ」→ 認証（誰か）と認可（何を許可するか）は別レイヤー。
  • 「トークンが有効なら全エンドポイント許可」→ スコープ/クレーム単位の制御が必要。
3分要点

3分要点（直前確認）

  1. 標準JWT検証だけなら HTTP API + JWT オーソライザーが第一候補。
  2. 独自判定（DB照会/属性ベース制御）が必要なら Lambda オーソライザー。
  3. AWS間呼び出し中心なら IAM 認可を検討。
