AWS DVA インプット（2026-05-25 JST）

試験範囲限定: 定義 / 重要性 / 使い分け / 誤解 / 3分要点

Topic 1: EventBridge ルールとターゲット

定義: EventBridge はイベントバス上のイベントをルールでフィルタし、Lambda/SQS/Step Functions 等へルーティングするサービス。

重要性: DVA では「疎結合」「フィルタ条件」「再試行/失敗先(DLQ)」の設計理解が頻出。

使い分け: 単純な時刻実行は Scheduler、イベント内容判定して複数ターゲット分岐は EventBridge ルール。

誤解: 「EventBridge がキューイングを保証する」は誤り。永続キューは SQS が担当。

3分要点: 1) イベントパターンは JSON マッチ 2) ターゲットごとに失敗処理設計 3) 監査は CloudWatch Logs + メトリクスで確認。

Topic 2: SQS Standard vs FIFO の設計判断

定義: Standard は高スループット・少なくとも1回配信、FIFO は順序保証と重複排除を提供。

重要性: DVA では「重複前提実装(idempotency)」「可視性タイムアウト」「DLQ設計」が重要。

使い分け: 順序不要で大量処理なら Standard。注文処理など順序厳守なら FIFO。

誤解: 「FIFO は常に遅い」は半分誤り。Message Group 設計で十分な並列性を確保可能。

3分要点: 1) 標準は重複を許容して設計 2) FIFO は group id を意識 3) 可視性タイムアウトは処理時間に合わせる。

Topic 3: Step Functions と Lambda オーケストレーション

定義: Step Functions は状態遷移で処理フローを可視化・再実行可能にするワークフローサービス。

重要性: DVA では「Retry/Catch」「サービス統合」「長時間処理の分離」が問われる。

使い分け: 単発変換は Lambda 単体、分岐・再試行・待機を含む処理は Step Functions。

誤解: 「Step Functions を使えば Lambda エラー対策不要」は誤り。関数側の例外分類と冪等性は必須。

3分要点: 1) 失敗時は Retry→Catch 2) 状態機械で可観測性向上 3) ワークフロー単位で責務分離。
