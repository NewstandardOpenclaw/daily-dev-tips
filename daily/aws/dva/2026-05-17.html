Topic 1: CloudWatch Logs Insights と CloudWatch Metrics/Alarms の役割分担

定義: Logs Insights はログをクエリして原因分析するツール。Metrics/Alarms は数値監視と閾値通知を行う監視基盤。

重要性: DVAでは「障害の予兆検知」と「障害後の原因分析」を混同させる選択肢が頻出。

使い分け:
・異常を即時検知して通知したい → Metrics + Alarms
・エラー発生条件や特定ユーザー影響を深掘りしたい → Logs Insights

誤解: 「Logs Insights だけでリアルタイム運用監視は十分」は誤り。継続的検知にはメトリクス設計が必要。

3分要点: 先に検知（Metrics/Alarms）、後で診断（Logs Insights）。この順序で覚えると問題を外しにくい。

Topic 2: Lambda 非同期呼び出しの再試行・DLQ・On-failure Destination

定義: 非同期Lambdaは失敗時に自動再試行される。DLQは失敗イベント保存先。Destinationは成功/失敗後のルーティング先。

重要性: 「失敗イベントをどこに残すか」「次にどう処理するか」はDVAの実装判断で定番。

使い分け:
・まず失敗記録を残したい → DLQ（SQS/SNS）
・失敗後に別ワークフローを起動したい → On-failure Destination（SQS/SNS/EventBridge/Lambda）

誤解: 「DLQとDestinationは同じ」は誤り。DLQは保管寄り、Destinationは連携寄り。

3分要点: 再処理の起点を作るならDestination、監査と保全中心ならDLQ。要件で主目的を先に決める。

Topic 3: DynamoDB GSI と LSI の設計判断（更新制約・一貫性・容量）

定義: GSIは別パーティションキーで柔軟な検索を追加できる二次インデックス。LSIは同一パーティションキー内で別ソートキー検索を提供。

重要性: DVAでは「クエリ要件」から正しいインデックス種別を選ぶ問題が頻出。

使い分け:
・ベーステーブルと異なるパーティションキーで検索したい → GSI
・同一パーティションで並び替え・範囲検索したい → LSI（テーブル作成時のみ定義）

誤解: 「LSIは後から追加できる」は誤り。LSIは作成時限定、GSIは後付け可能。

3分要点: まず検索軸が“同一PKか別PKか”を確認。同一PKならLSI候補、別PKならGSI一択に近い。
