Topic 1: IAMロール vs Cognito vs STS（一時認証情報）

定義: IAMロールは権限の器、STSは一時クレデンシャル発行、Cognitoはアプリユーザー認証とID連携を提供。

重要性: DVAは「誰が、どこから、どの権限でAWS資源に触るか」を設計できるかを問う。

使い分け:
・AWSサービス間権限委譲（EC2→S3）→ IAMロール
・外部ID/OIDC連携で短期資格情報発行 → STS AssumeRole
・モバイル/Webのユーザー認証基盤 → Cognito User Pools + Identity Pools

誤解: 「CognitoがあればIAM不要」ではない。最終的にAWS API実行権限はIAMポリシーで制御する。

3分要点: 認証(Identity)と認可(Authorization)を分離。Cognitoで本人確認、STSで短期鍵、IAMで最小権限。

Topic 2: DynamoDB DAX vs ElastiCache（Redis）

定義: DAXはDynamoDB専用のインメモリキャッシュ、ElastiCache Redisは汎用キャッシュ/データ構造ストア。

重要性: 試験で「読み取り高速化」の選択肢として頻出。要件に対する過不足を見抜く必要がある。

使い分け:
・DynamoDB API互換で最小改修の高速化 → DAX
・複雑なTTL/ランキング/分散ロック/PubSub → Redis

誤解: 「DAXはDynamoDBを常に最新化する」わけではない。結果整合読み取りとキャッシュ失効設計を意識する。

3分要点: DynamoDB前提ならまずDAXを検討。要件がキャッシュを超えてデータ構造活用へ広がるならRedis。

Topic 3: CodeDeploy Blue/Green と Rolling の判断軸

定義: Rollingは段階更新、Blue/Greenは新旧環境を並行させて切替するデプロイ方式。

重要性: 可用性要件・ロールバック速度・コスト制約に応じた選定問題がDVAでよく出る。

使い分け:
・追加コストを抑えつつ漸進更新 → Rolling
・切替失敗時に即時戻ししたい/停止を最小化 → Blue/Green

誤解: 「Blue/Greenは常に無停止」ではない。DBスキーマ互換やセッション管理を誤ると影響が出る。

3分要点: 信頼性最優先ならBlue/Green、コスト最優先ならRolling。事前にヘルスチェックとロールバック条件を明文化。
