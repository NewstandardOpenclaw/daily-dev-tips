IAMロールと一時認証情報
  • これは何か: AWSリソースに権限を安全に付与するための仕組み。長期アクセスキーを配布せず、一時的な認証情報を使う。
  • なぜ重要か: 漏えいリスクを下げ、ローテーション運用の負荷を減らせる。
  • 使いどころ/使い分け: EC2/Lambda/ECS はロール、開発者は最小権限のIAMユーザー/SSOを使い分ける。
  • よくある誤解: アクセスキーをアプリ設定に直書きすれば早いと考えること。
  • 3分要点: 「キーを配らない」が実務でも試験でも最重要。

参考: AWS Docs

DynamoDBのRCU/WCU設計
  • これは何か: 読み書き容量を見積もるためのスループット単位。
  • なぜ重要か: 過不足のない性能・コスト設計に直結する。
  • 使いどころ/使い分け: オンデマンドとプロビジョンドをアクセス特性で選ぶ。
  • よくある誤解: 最初は常に最小設定でよいと思うこと。
  • 3分要点: アクセスパターンから逆算して容量を決める。

参考: AWS Docs

S3署名付きURL
  • これは何か: 期限付きで特定オブジェクトにアクセス許可するURL。
  • なぜ重要か: 安全にクライアント直アップロード/ダウンロードを実現できる。
  • 使いどころ/使い分け: アプリサーバーを経由せずにS3連携したいとき。
  • よくある誤解: 無期限URLで運用してしまうこと。
  • 3分要点: 期限・権限・対象キーを最小化する。

参考: AWS Docs

SQS + DLQ
  • これは何か: 失敗メッセージをDLQに退避して本流を守る構成。
  • なぜ重要か: 一時障害で全体停止しない堅牢な非同期処理を作れる。
  • 使いどころ/使い分け: 外部API連携・バッチ処理の失敗隔離。
  • よくある誤解: 再試行だけ増やして根本原因を放置すること。
  • 3分要点: 再試行回数とDLQ監視はセット。

参考: AWS Docs

Lambda同時実行とスロットリング
  • これは何か: 同時実行数の上限と保護制御。
  • なぜ重要か: 下流システムを守りつつ安定運用できる。
  • 使いどころ/使い分け: RDS接続枯渇や外部API制限への対策。
  • よくある誤解: 上限を上げ続ければ解決するという発想。
  • 3分要点: 下流の許容量に合わせて制御する。

参考: AWS Docs

API Gateway認可方式
  • これは何か: IAM/Cognito/Lambda AuthorizerでAPIアクセスを制御。
  • なぜ重要か: 公開APIの安全性と運用性に直結。
  • 使いどころ/使い分け: B2BはIAM、ユーザー向けはCognitoなど要件で選ぶ。
  • よくある誤解: 全部Lambda Authorizerに寄せること。
  • 3分要点: 認証方式は利用者と要件で決める。

参考: AWS Docs

CloudWatch Logs Insights
  • これは何か: ログをクエリして障害調査を高速化する機能。

X-Rayトレーシング
  • これは何か: 分散処理の遅延ポイントを可視化する仕組み。
  • なぜ重要か: どこで遅いかを素早く特定できる。

  • よくある誤解: メトリクスだけで原因特定できると思うこと。
  • 3分要点: trace_idで処理経路を追う。
