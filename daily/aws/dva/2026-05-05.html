Topic 1: DynamoDB の Strongly Consistent Read と Eventually Consistent Read

定義: GetItem/Query/Scan の読み取りは、強い整合性（最新書き込みを反映）か結果整合性（遅延反映あり）を選べる。

重要性: DVAでは「最新値が必要か」「コスト最適化優先か」を問う問題が頻出。結果整合性はRCU消費を抑えられる。

使い分け: 決済直後の残高照会など誤差NGは強整合。タイムライン表示や集計閲覧は結果整合で十分。

よくある誤解: 「DynamoDBは常に強整合」ではない。既定は結果整合で、明示指定が必要。

3分要点: “今この瞬間の正確さ”が要件なら強整合、そうでなければ結果整合でコスト効率を取る。

Topic 2: AWS SDK のデフォルト資格情報チェーン（EC2/ECS編）

定義: SDKは環境変数→共有設定→実行環境ロール（EC2 Instance Profile / ECS Task Role）などを順に探索して認証情報を取得する。

重要性: 試験では「アクセスキーを直書きしない」設計が基本。実運用でも漏えい対策とローテーション負荷削減に直結。

使い分け: EC2はインスタンスプロファイル、ECSはタスクロールを第一選択。ローカル開発のみプロファイル併用。

よくある誤解: 「環境変数のキーを置けば十分安全」は誤り。配布や管理の観点で長期キーが残る運用は危険。

3分要点: 本番は“ロールで渡す”が正解。コード内にキーを置かない設計がDVAの王道。

Topic 3: SQS 可視性タイムアウトと重複処理対策

定義: メッセージ受信後、可視性タイムアウト中は他コンシューマから見えない。削除前にタイムアウトすると再配信される。

重要性: DVAは「少なくとも1回配送」を前提に設計できるかを見る。重複実行前提の実装力が問われる。

使い分け: 処理時間が読めるなら固定値、長時間ジョブは ChangeMessageVisibility で延長しつつ処理。

よくある誤解: 「SQSなら一度しか処理されない」は誤り。標準キューは重複の可能性があるため冪等性が必須。

3分要点: タイムアウト値と処理時間を合わせる＋冪等キーで二重反映を防ぐ。
