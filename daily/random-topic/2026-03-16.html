CRDTの実務導入ポイント
  • 定義: 競合しても最終的に整合するデータ型（Conflict-free Replicated Data Type）。
  • 重要性: オフライン編集や多拠点同時編集で競合解決コストを下げられる。
  • 使い分け: テキスト共同編集やカウンタ同期で有効。厳密トランザクション領域には不向き。
  • よくある誤解: CRDTならどんな業務整合性も担保できるという誤解。
  • 3分要点: 「可換操作で収束するか」を先に検証する。

参考: crdt.tech / Local-first

質問テンプレ: 「CRDTを、定義→重要性→使い分け→誤解→3分要点の順で、実務ユースケース付きで解説してください。」
WASMランタイム選定
  • 定義: WebAssemblyバイナリを実行する環境（ブラウザ/サーバー）を用途で選ぶ判断。
  • 重要性: 同じWASMでもランタイム差で起動時間・拡張性・セキュリティが変わる。
  • 使い分け: エッジ実行は軽量重視、サーバー実行はI/O連携と観測性を重視。
  • よくある誤解: 一度WASM化すればどこでも同じ性能という誤解。
  • 3分要点: 起動時間・メモリ上限・ホスト関数設計を比較軸にする。

参考: WebAssembly Docs / Wasmtime

質問テンプレ: 「WASMランタイム選定を、定義→重要性→使い分け→誤解→3分要点の順で比較表付きで説明してください。」
QUIC/HTTP3の運用視点
  • 定義: UDPベースで多重化・接続再開を強化した次世代HTTP通信。
  • 重要性: モバイル回線など不安定ネットワークで体感速度改善が期待できる。
  • 使い分け: 静的配信・API入口に段階導入し、フォールバック経路を必ず残す。
  • よくある誤解: HTTP/3化だけでバックエンド遅延も解決するという誤解。
  • 3分要点: まずCDN側で有効化し、転送層改善効果を計測する。

参考: RFC 9000 / Cloudflare HTTP/3

質問テンプレ: 「QUIC/HTTP3を、定義→重要性→使い分け→誤解→3分要点の順で、導入手順付きで解説してください。」
差分プライバシー入門
  • 定義: 個々のデータ寄与をノイズで保護し、統計的有用性を維持する匿名化手法。
  • 重要性: 分析価値を保ったまま個人情報漏洩リスクを抑えられる。
  • 使い分け: 集計公開やログ分析で有効。個票レベル出力には別対策が必要。
  • よくある誤解: ノイズを足せば法令対応が完全になるという誤解。
  • 3分要点: ε（イプシロン）予算管理を設計時に明示する。

参考: Harvard DP / OpenDP

質問テンプレ: 「差分プライバシーを、定義→重要性→使い分け→誤解→3分要点の順で、実装時の注意点込みで解説してください。」
GPUメモリ断片化対策
  • 定義: GPUメモリの割当/解放の偏りで利用効率が下がる問題を抑える設計。
  • 重要性: OOM頻発を抑え、推論サービスの安定稼働に直結する。
  • 使い分け: バッチサイズ固定化、メモリプール活用、モデル常駐戦略を併用する。
  • よくある誤解: GPU容量を増やせば断片化問題は消えるという誤解。
  • 3分要点: メモリ使用推移を時系列で観測し、ピーク前後の割当パターンを特定する。

参考: PyTorch CUDA Notes / NVIDIA Docs

質問テンプレ: 「GPUメモリ断片化対策を、定義→重要性→使い分け→誤解→3分要点の順で、現場チェック項目付きで解説してください。」
