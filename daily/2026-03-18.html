IAMロールと一時認証情報
  • これは何か: EC2/Lambda/ECSに長期キーを置かず、一時クレデンシャルでAPI実行する方式。
  • なぜ重要か: 漏えいリスク低減と運用負荷削減に直結。
  • 使いどころ/使い分け: アプリ実行環境にはロール、開発者には最小権限ポリシーを分離。
  • よくある誤解: アクセスキーを環境変数に直書きすること。
  • 3分要点: 「キーを配らない設計」がDVAの基本。

参考: AWS Docs / ChatGPT / Gemini

DynamoDB パーティションキー設計
  • これは何か: アクセスパターンに合わせてパーティションキーを決める設計。
  • なぜ重要か: ホットパーティション回避が性能とコストを左右する。
  • 使いどころ/使い分け: 高頻度アクセスは分散キー、集約はGSIで補う。
  • よくある誤解: 後からキー変更が簡単だと思うこと。
  • 3分要点: まずクエリから逆算して設計する。

参考: AWS Docs / ChatGPT / Gemini

SQS + Lambda 再試行制御
  • これは何か: キューを介して非同期処理し、失敗時は再試行・DLQへ退避する設計。
  • なぜ重要か: 一時障害で全体停止しない堅牢性を作れる。
  • 使いどころ/使い分け: 外部API呼び出しや重い処理の非同期化。
  • よくある誤解: 無限リトライで障害を悪化させること。
  • 3分要点: 再試行回数とDLQ運用をセットで設計。

参考: AWS Docs / ChatGPT / Gemini

API Gateway 認証方式
  • これは何か: IAM/Cognito/Lambda AuthorizerでAPIアクセスを制御する。
  • なぜ重要か: 公開APIの安全性と運用負荷に直結。
  • 使いどころ/使い分け: 社内APIはIAM、ユーザーAPIはCognitoが基本線。
  • よくある誤解: 全部Lambda Authorizerで統一すること。
  • 3分要点: 要件別に認証方式を使い分ける。

参考: AWS Docs / ChatGPT / Gemini

Lambda コールドスタート対策
  • これは何か: 初回起動遅延を依存削減・メモリ調整・プロビジョンド同時実行で抑える。
  • なぜ重要か: 体感遅延やタイムアウトを防げる。
  • 使いどころ/使い分け: 低遅延が必要なAPIエンドポイント。
  • よくある誤解: メモリを下げれば安いだけと考えること。
  • 3分要点: 性能とコストは計測して最適点を探す。

参考: AWS Docs / ChatGPT / Gemini

CloudWatch Logs Insights
  • これは何か: ログをクエリして障害原因を素早く絞り込む機能。
  • なぜ重要か: 調査速度がそのまま復旧速度になる。
  • 使いどころ/使い分け: requestIdやuserId単位の追跡。
  • よくある誤解: ログに相関キーを入れないこと。
  • 3分要点: まず検索しやすいログを作る。

S3 署名付きURL
  • これは何か: 期限付きで限定アクセスを許可するURL発行方式。
  • なぜ重要か: 安全に直接アップロード/ダウンロードさせられる。
  • 使いどころ/使い分け: フロントからS3直アップロードする構成。
  • よくある誤解: 無期限公開URLにすること。
  • 3分要点: 期限・権限・対象キーを最小に絞る。

  • これは何か: 機密情報管理と設定管理を用途で使い分ける。
